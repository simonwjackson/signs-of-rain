# RG353M on Korri

The native Linux package supports x86_64 and ARM64. Build on a workstation, never on the handheld:

```sh
nix build --option builders '' .#packages.aarch64-linux.signs-of-rain
```

The ARM package contains the exact ARM64 Godot 4.6.1 runtime. An x86 build host exports the shared resource pack. The package uses cached native dependencies rather than compiling on the device. A cache miss still needs a separate off-device builder. The initial ARM dependency download was 273.5 MiB and used about 1.1 GiB unpacked.

The ARM launcher selects Compatibility with `opengl3_es`. Mesa documents conformant GLES 3.1 on Mali-G52. Its Vulkan support is experimental and non-conformant. We do not enable `PAN_I_WANT_A_BROKEN_VULKAN_DRIVER`. The compositor's `gles2` setting does not select the game's renderer. See [Mesa's driver table](https://docs.mesa3d.org/drivers/panfrost.html).

The personal plugin selects `--handheld --graphics=fast`. This retains the 3D valley, all 24 animated people, simulation, audio, and camera. It removes the glow pass and uses a 1024-pixel sun-shadow atlas with 60-meter coverage. Fast keeps the existing lower 3D resolution. The CPU ceiling stays at Korri's recorded 1.104 GHz. No kernel, driver, clock, compositor or service change is part of this package.

Cost: lighting loses glow, distant shadows disappear earlier, and the lower-resolution world loses sharpness. Desktop and Android defaults remain unchanged. Compatibility cannot use SSAO, SSIL or volumetric fog. Source-derived geometry counts show that vegetation and terrain still deserve measurement. These changes do not establish 60 FPS.

## Controller

| Input | Action |
|---|---|
| Left stick | Pan the camera. |
| Right stick | Orbit and tilt. In sheets, scroll. Hold its stick button to scroll a person's account. |
| Shoulder buttons | Zoom. |
| A | Select or give at the center crosshair. In sheets, activate the focused control. |
| B | Close a sheet, clear selection, or cancel a gift. |
| X / Y | Select Rain / Food. |
| D-pad left / right | Select previous / next person. |
| D-pad up / down | Show the selected person / whole valley. |
| Start | Pause or resume. Start the intro or close a sheet. |
| Select | Open the complete action menu. |

The menu includes speed, people, replay, saving, restart, sound, motion, graphics, help and quit. The 640×480 controller tests check account scrolling, a visible world target outside the inspector, and focus confined to the action sheet. Native focus drives sheets and their lists follow focus. Modal changes, focus loss and disconnect cancel held camera input. Mouse, touch and keyboard remain supported.

## Verification and limits

The real engine tests route joystick events through the scene and check camera movement, gift placement, modal focus, cancellation and all 24 people. They are not physical-button acceptance. Both Linux packages build off-device. The ARM ELF identifies AArch64. The x86 pack smoke test loads the exported game. An owned 640×480 X server also rendered the scene and menu with Compatibility/GLES on llvmpipe. The captures include all 24 people and no shader or engine errors. Software rendering on a workstation does not prove Mali performance, ARM GLES rendering or device audio.

With the existing opt-in `--evidence=/absolute/path.json`, the game reports process-delta frame intervals, a bounded 3600-frame window with p50/p95/p99, a lifetime maximum, over-budget count, renderer and render counters. No timings are collected without that option. Process delta is not a hardware presentation timestamp or GPU timer. Evidence collection adds overhead. Paused or ended gameplay does not count as sustained active-game acceptance.

For 60 Hz, each frame has a 16.67 ms budget. Before a claim, verify the actual Mali graphics context, compile shaders, inspect a screenshot, exercise close/overview views and miracles, and collect sustained active-game frame times plus temperature and throttling. Test at the existing CPU ceiling. Average FPS alone is insufficient. Physical controls, audio, heat, ARM replay equivalence and sustained 60 FPS remain unverified until an owner-approved device session.

Plugin source lives in [simonwjackson/korri-plugins](https://github.com/simonwjackson/korri-plugins). It matches the packaged PCK's actual SHA-256, not arbitrary Godot files. Its native program and account-owned Godot data follow Korri's existing launch contract. Installation still needs normal publisher trust, package approval and a library record for the exact PCK. Publishing source does not install or enable the plugin.
